You are analyzing this Replit app for handoff to another senior AI coding assistant.

Goal:
Create a detailed, accurate, implementation-level app brief so the next assistant can understand the full product, architecture, codebase, current state, and what to modify next without re-discovering everything.

Important rules:
- Do not guess.
- Verify every claim from actual files.
- Mention exact file paths.
- If something is unclear, say “unclear” and name the files that need inspection.
- Do not expose secret values from .env or Replit secrets. Only mention variable names.
- Prefer concrete details over generic explanation.
- Include enough detail that another assistant can continue development immediately.

Analyze and report the following:

1. Product Overview
- What this app is trying to do in simple business language
- Who the users are
- What problem it solves
- What the current app appears optimized for: demo, MVP, production, landing page, dashboard, marketplace, etc.

2. Tech Stack
- Frontend framework and version
- Backend framework and version
- Database/storage used
- Auth used
- Payment/email/file upload/AI integrations, if any
- Styling/UI libraries
- Build tools
- Package manager
- Hosting/deployment assumptions
- Cite the exact files where each was found

3. Project Structure
Give a folder tree summary.
For each important folder/file, explain:
- purpose
- key exports/components/functions
- how it connects to the rest of the app

4. Routes and Pages
List every route/page/screen.
For each:
- URL/path
- file path
- what user sees
- key components
- forms/buttons/actions
- API calls made
- current completion level

5. User Flows
Describe complete flows step by step:
- company/recruiter flow
- student/candidate flow
- admin/founder flow if any
- auth flow if any
- submission/contact/lead capture flow
- any onboarding flow

For each flow, mention:
- entry point
- data collected

- success/error states
- missing pieces

6. Data Model
If database/schema exists, document:
- tables/models/collections
- fields
- relationships
- validation rules

- file

9. UI / Design System

10. Current Features

14. Files To Read First
Rank the top 10 files another assistant should inspect first.

15. Recommended Next Development Steps
Give a prioritized list of what should be done next to make this app useful for validating demand:
- must do before showing customers

Keep this section practical and specific to this app.

16. Final Handoff Summary
End with:
- “The app currently is: …”

Use clear Markdown headings.
